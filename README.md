# PSD_eNGINNo Chiller Plant Analytic System

เว็บแอปวิเคราะห์ Chiller plant (Chiller / CHP / CDP / Cooling tower) จากไฟล์ Excel log รายเดือน
ไฟล์เดียว `index.html` เปิดใช้งานได้เลย ไม่ต้องมี server

## ฟีเจอร์
- โลโก้ BHIRAJ BURI GROUP มุมซ้ายบน (ไฟล์ `src/logo.png`)
- ปุ่ม **เดือน / สัปดาห์ / วัน** ที่แถบด้านบน: ทุกหน้าวิเคราะห์ (ภาพรวม, Chiller, CHP, CDP, Cooling tower, ดีที่สุด, ชุดอุปกรณ์) แบ่งช่วงตามหน่วยที่เลือก · ค่าเริ่มต้นแสดงถึงช่วงล่าสุดเสมอ (เดือน: เม.ย. 69 → เดือนล่าสุด · สัปดาห์: 8 สัปดาห์ล่าสุด จันทร์–อาทิตย์ · วัน: 7 วันล่าสุด) · หน้าก่อน–หลังปรับปรุง, Regression และรายงานส่งออกยังคิดเป็นรายเดือน
- ซิงก์ข้อมูลจาก Google Sheet แบบ real time ผ่าน Apps Script (ดูหัวข้อด้านล่าง)
- Login / Register: ผู้ลงทะเบียนต้องให้ผู้ดูแล (admin) อนุมัติก่อนใช้งาน
- ภาพรวม: kW/TRp, kWh ทั้ง plant (kW × 2 ชม./บันทึก), เทียบเกณฑ์ประสิทธิภาพ, แนวโน้มรายเดือน
- วิเคราะห์รายตัวรายเดือน: Chiller, CHP, CDP, Cooling tower
- ก่อน–หลังปรับปรุง พร้อมผลประหยัดเทียบ baseline
- Chiller ดีที่สุดรายเดือน / ชุดอุปกรณ์ kW/TRp ต่ำสุด / Regression (R² > 80%, P < 0.05)
- ธีมพื้นหลัง 3 แบบ (เทา-ขาว, มืด, ฟ้าทะเล) และสีตัวอักษร 3 แบบ (ดำ, ส้ม, น้ำเงิน) ที่หน้า "ข้อมูลและการตั้งค่า" และฟอนต์ (Orbitron, Courier New, Sarabun, หรือค่าเริ่มต้น IBM Plex Sans Thai)
- เมนู "ความผิดปกติของข้อมูล" (กลุ่มการวิเคราะห์): แจ้งเตือนค่าผิดปกติ รายการวันที่-เวลา-ชุด และย้ายไป History เมื่อช่างแก้ไขแล้ว พร้อมบันทึกรายละเอียดการแก้ไข · หน้าอื่นมีแถบเตือนสั้นและป้าย ⚠ บนตาราง
- โหมดคำนวณหน้าภาพรวม: "เฉพาะค่าปกติ" หรือ "รวมทั้งหมด" (วิธีเดียวกับ dashboard) เลือกที่หน้าข้อมูลและการตั้งค่า · kWh นับทุกบันทึกในทั้งสองโหมด
- หน้า "ข้อมูลและการตั้งค่า": ดูรายการวันที่-เวลา-ชุดที่ถูกตัดออกจากการวิเคราะห์ พร้อมบอกว่าสูง/ต่ำกว่าช่วง, เทียบค่าเฉลี่ยกับ dashboard, ดาวน์โหลดเป็น Excel
- นำเข้าข้อมูลรายเดือนจาก .xlsx หรือ **วางข้อมูลที่คัดลอกจาก Google Sheet** (เฉพาะ admin) / ส่งออกรายงาน HTML และ Excel

## วางข้อมูลจาก Google Sheet
ปุ่ม "นำเข้าข้อมูล" → แท็บ "วางจาก Google Sheet" → ใน Sheet คลิก A1, Ctrl+A, Ctrl+C แล้ววางในช่อง (ต้องมีแถวหัวคอลัมน์)
ไม่ต้องเชื่อม Google Drive แอปอ่านเฉพาะข้อความที่วาง

## เชื่อม Google Sheet แบบ real time (Apps Script)
1. เปิด Google Sheet ที่เก็บบันทึก → ส่วนขยาย → Apps Script → วางโค้ดจาก `tools/apps_script_Code.gs` → แก้ `KEY` เป็นรหัสลับของคุณ
2. Deploy → การทำให้ใช้งานได้รายการใหม่ → ประเภท **เว็บแอป** · ดำเนินการในฐานะ: **ฉัน** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน** → คัดลอก URL ที่ลงท้าย `/exec`
3. ทดสอบในเบราว์เซอร์: `<URL>?key=<KEY>&months=1` ต้องได้ `{"ok":true,...}`
4. ให้ทุกคนซิงก์ได้: แก้ `window.PSD_SYNC = { url:'...', key:'...' }` ใน `index.html` (ค้นคำว่า PSD_SYNC) แล้วอัปโหลดขึ้น GitHub
   หรือทดลองเฉพาะเครื่องตัวเอง: หน้า "ข้อมูลและการตั้งค่า" → เชื่อมต่อ Google Sheet (admin)
- สคริปต์อ่านอย่างเดียว ไม่แก้ไขชีต และชีตไม่ต้องแชร์ลิงก์ · ไม่มี KEY จะได้ `{"ok":false}`
- webapp ซิงก์ตอนเข้าใช้งาน และทุก 5 นาที (ปรับได้) · ครั้งแรกดึงทั้งหมด จากนั้นดึงเฉพาะ 2 เดือนล่าสุด และบันทึกเฉพาะเดือนที่เปลี่ยน · ปุ่ม ⟳ ที่แถบบนกดซิงก์ทันที
- KEY ที่ใส่ใน index.html ใครเปิดซอร์สได้ก็เห็น → ใช้ repository แบบ **Private**
- ใช้งานซิงก์บน GitHub Pages (หน้า claude.ai artifact ไม่อนุญาตให้ดึงข้อมูลจากเว็บภายนอก)
- แก้โค้ดสคริปต์แล้ว: Deploy → จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่ (URL เดิม)

## 3D Plant
ปุ่ม **◈ 3D Plant / ▤ หลังบ้าน** ที่แถบบน · ผังออกแบบเองจากแบบ 2MFL/3MFL: ซ้าย Cooling tower (ชั้น 3M, 3 กลุ่ม) → CDP → กลาง Chiller 12 ชุด → ขวา PCHP · ด้านหน้า SCHP/H-SCHP
- ข้อมูล ณ เวลาที่เลือก (ค่าเริ่มต้น = บันทึกล่าสุด) · ◀ ▶ / เล่นย้อนหลัง · คลิกเครื่องดูรายละเอียด
- สี: ทำงาน = ฟ้า + เคลื่อนไหว (พัดลม CT, ปั๊ม, การไหลในท่อ) · Standby = เขียว · ชำรุด/ค่าผิดปกติ = แดงกะพริบ · ไม่มีข้อมูล = เทา
- Chiller ทำงาน = มีบันทึกในเวลานั้น · PCHP/CDP ตามชุด chiller · CT จาก Cooling(kW)_xx · SCHP จากคอลัมน์ Record_(kW)_SCHP-xx (ถ้ามีในไฟล์)
- ค่าผิดปกติ = บันทึกไม่ผ่านเกณฑ์ · ชำรุด = admin แจ้งเองในหน้า 3D (เก็บในเบราว์เซอร์นั้น)
- ใช้ three.js r128 (cdnjs) + OrbitControls (jsdelivr) โหลดเมื่อกดเข้า 3D ครั้งแรก

## Ai-eNGINNo (AI Analytics ด้วย Claude) — admin เท่านั้น
เมนู "การตั้งค่าข้อมูลระบบ" → **✦ Ai-eNGINNo** (ใต้ "จัดการผู้ใช้") · 4 หัวข้อ: วิเคราะห์ประสิทธิภาพ · สาเหตุ kW/TRp สูง · ปัญหาที่ต้องแก้ด่วน · คำแนะนำและสรุป + Auto Analyze + แชตถามต่อ
- ใช้ Web App URL/KEY เดียวกับการซิงก์ (ต้องวางโค้ด `tools/apps_script_Code.gs` เวอร์ชันใหม่ที่มี `doPost` แล้ว Deploy เป็นเวอร์ชันใหม่)
- Apps Script → ⚙ ตั้งค่าโปรเจกต์ → Script properties: `CLAUDE_API_KEY` = API key ของ Claude, `AI_PASSWORD` = รหัส 12 ตัวอักษร
- API key อยู่ใน Google เท่านั้น ไม่อยู่ใน index.html · หน้าเว็บส่งเฉพาะข้อมูลสรุป (ดูได้ที่ "ข้อมูลที่ส่งให้ AI") ไม่ส่งบันทึกดิบ
- รหัส AI จำไว้เฉพาะแท็บนั้น (ล้างเมื่อปิดแท็บ/ออกจากระบบ/กด ล็อก AI) · รหัสผิด 5 ครั้ง = ล็อก 15 นาที · จำกัด 40 คำขอ/ชั่วโมง
- เปลี่ยนรุ่นโมเดลที่ `AI_MODEL` ในสคริปต์ · ใช้งานบน GitHub Pages (หน้า claude.ai artifact ไม่อนุญาตให้เชื่อมต่อภายนอก)

## ข้อจำกัดด้านความปลอดภัย (สำคัญ)
- ระบบ Login ทำงานในเบราว์เซอร์ทั้งหมด เป็นเพียงด่านกั้นสำหรับทีมขนาดเล็ก **ไม่ใช่ความปลอดภัยระดับเซิร์ฟเวอร์**
  ใครเปิดดูซอร์สหรือ DevTools ได้ก็เห็นข้อมูลตั้งต้น (`src/seed.json`) และ hash ของรหัสผ่าน admin ได้
- บน GitHub Pages รายชื่อผู้ใช้เก็บใน IndexedDB ของแต่ละเบราว์เซอร์ ผู้ลงทะเบียนบนเครื่องหนึ่งจึงไม่ไปปรากฏที่ admin บนอีกเครื่อง
  ถ้าต้องการอนุมัติข้ามเครื่องจริง ต้องเพิ่มฐานข้อมูลฝั่งเซิร์ฟเวอร์ (เช่น Firebase / Supabase)
- ใช้ repo แบบ Private ถ้าข้อมูล log เป็นความลับ และเปลี่ยนรหัสผ่าน admin ด้วย `tools/make_admin_hash.py`
